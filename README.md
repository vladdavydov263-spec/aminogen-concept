# AMINOGEN — концепт сайта (UA)

Сайт на украинском (глоссарий — `GLOSSARY-UK.md`), рынок — Украина: доставка «Новою поштою», оплата карткой или переводом, цены в гривне (демонстрационные).
Статическая страница без сборки: `index.html` + CSS + JS. Открывается двойным кликом,
но локальный сервер надёжнее (нужен для `?lot=` и для одинакового поведения шрифтов):

```bash
cd concept
node server.js          # http://127.0.0.1:8765
node server.js --dump   # показать сохранённые анкеты и заказы
```

`server.js` — ноль зависимостей, Node 18+. Отдаёт статику и два эндпоинта:

| Эндпоинт | Что делает |
|---|---|
| `POST /api/intake` | принимает анкету программы, валидирует, считает BMI, пишет в `data/intake.jsonl`, возвращает номер `MC-…` |
| `POST /api/order` | принимает заказ, **пересчитывает цены на сервере** (клиент не может подставить свою), пишет в `data/orders.jsonl`, возвращает `ORD-…` |
| `GET /api/health` | проверка живости |

Кабинета нет: клиент получает только номер обращения, данные читаются файлами (`--dump`).
Анкета и заказ отправляются с фронта через `fetch`; если сервер недоступен (например, страница
открыта как файл), интерфейс честно падает в demo-режим и пишет, что ничего не отправлено.

| `care/start.html` | анкета-скрининг: 6 шагов (цель → рост/вес/BMI → история болезней → лекарства → контакты → согласия) → результат для врача → запись на консультацию |

Кабинета нет: после записи флоу заканчивается экраном с номером обращения. Анкета ничего не
отправляет — данные живут в браузере, внизу подписано «demo, no data transmitted». Цены, сроки
и наличие партнёров (клиника, аптека) — плейсхолдеры, их нужно заменить реальными.

## Витрина (B2C)

| Файл | Что внутри |
|---|---|
| `shop/index.html` | магазин: промо-полоса, каталог с ценами, корзина-шторка, «как это работает», FAQ, RUO |
| `shop/checkout.html` | оформление: контакты, доставка, оплата (Card / BLIK / Transfer), сводка заказа, экран успеха |
| `shop/quiz.html` | квиз-подбор: 4 шага (область → вещество → дозировка → объём), прогресс, «назад», результат с ценой и кнопкой в корзину |

Корзина живёт в `localStorage`, переживает перезагрузку. Товар можно добавить ссылкой:
`/shop/?cart=tir-15:2,ret-20:1` — это же будет использоваться для кнопки «Купить» на карточке товара.
Суммы, доставка (бесплатно от €200, иначе €15) и цены — **демонстрационные**, в футере подписано
«sample prices». Оплата не подключена: чекаут показывает экран успеха и ничего не списывает.

Важно: витрина продаёт товар как исследовательский материал — без дозировок, обещаний
похудения и отзывов о результате. Это единственная конфигурация, которая не является
незаконным оборотом лекарств и не блокируется эквайрингом. Модель «программа с врачом»
(квиз → консультация → рецепт → аптека-партнёр) — отдельный этап, требует медпартнёра.

## Данные, которые в концепте условные

- **Демо-лоты и цифры в batch verification** — иллюстрация интерфейса, не реальные COA.
  Реальные отчёты Janoshik подставляются в `LOTS` в `main.js` (позже — в JSON/базу).
- **Продуктовые фото** — AI-рендеры коробки из чата. Для запуска нужны настоящие фото
  продукта и лаборатории.
- **Chemspec-API и Janoshik** описаны как партнёры в терминах, которые есть в переписке
  («рассматриваемый производственный партнёр»). Формулировки на сайте нужно подтвердить
  договором/документами до публикации.
- **Цены** не публикуются: в чате нет утверждённого розничного прайса, поэтому CTA —
  «Request price».
- **Отзывов нет** — сознательно. В чате обсуждалась накрутка и «независимые» статьи,
  оплаченные брендом; в концепт это не заложено. На `reviews.html` стоят карточки-макеты
  с пометкой *Sample layout*: формат показан, тексты и цифры не придуманы.
- **Люди** на `about.html` — карточки по ролям (инициалы, без имён и фото). Реальные фото
  команды и лаборатории нужно добавить.
- **Политики** — рабочий каркас, не юридические документы: `[legal entity name]`, адрес,
  номер компании, юрисдикция и сроки заполняются вами, финальный текст проверяет юрист.
  Копировать дословно у конкурентов нельзя: там другие юрлица и другая юрисдикция.

## Отзывы: как это устроено и где ограничение

Страница сделана по вашему принципу: продукт и документы — на карточке товара, отзывы — отдельно.
Публикуется только то, что можно проверить: номер заказа, номер партии, письменное согласие,
текст без правок. Два формата карточек: сервисный отзыв и история результата (продукт + срок).

Ограничение, которое нужно решить до запуска: пока продукт позиционируется как *research use
only*, публикация результатов «похудела на N кг» — это прямое доказательство применения
человеком, то есть противоречие собственному дисклеймеру и аргумент против вас для регулятора
и платёжного провайдера. Варианты:
1. RUO-модель: на сайте только сервисные отзывы (доставка, документы, поддержка);
2. модель MERQANO (клиника + рецепт): истории результатов законны, но нужен медицинский
   партнёр, согласия и другая юридическая обвязка;
3. отдельный закрытый раздел для партнёрских клиник.

Разбор конкурентов (Origin46, Bodi Envi, Polski Peptyd, Novaryn) — в [COMPETITORS.md](COMPETITORS.md):
главное там про разницу telehealth-воронки и research-магазина.

## Мини-CRM

Встроена в `server.js`, отдельной базы не требует.

- Вход: `http://127.0.0.1:8765/crm?token=<CRM_TOKEN>` (токен печатается при старте, либо задаётся `CRM_TOKEN=...`).
- Показывает анкеты программы и заказы магазина: клиент, область, BMI/состав заказа, сумма, статус (`new → reviewing → approved → declined → shipped → done`), заметка.
- Статусы и заметки хранятся в `data/status.json` (не в git).
- **Експорт CSV:** `/crm/export?token=...` — открывается в Excel/Sheets.
- **Уведомления:** если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, каждая новая анкета/заказ приходит в Telegram. Если задан `CRM_WEBHOOK_URL` — событие уходит POST-ом в любую внешнюю CRM (KeyCRM, Kommo, HubSpot, Make/n8n).

```bash
CRM_TOKEN=мой-токен \
TELEGRAM_BOT_TOKEN=123456:AA... \
TELEGRAM_CHAT_ID=-100123456789 \
node server.js
```

Важно: CRM живёт только на Node-сервере. На GitHub Pages (статика) её нет — там формы работают в демо-режиме.
